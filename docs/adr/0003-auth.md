# ADR-0003. JWT і рольова модель

Статус: прийнято; зафіксовано у С9 (24.11.2026).

## Контекст

Переглядач читає дані, агроном змінює пороги. Потрібен контроль дій незалежно від UI.

## Розглянуті варіанти

1. JWT access + opaque refresh, ролі agronomist / viewer — один механізм для REST і socket.
2. Серверні сесії — можливі, але для socket та REST потрібно узгоджувати сесійні cookies; спільний пароль — не забезпечує індивідуального аудиту.

## Рішення

JWT з перевіркою HS256, ротацією refresh і рольовим middleware.

## Наслідки

Ключ треба захищати; токен живе до exp; refresh зберігається в БД як SHA-256; демо-облікові записи не для production.

Підтвердження в коді: `auth/routes.js`, `auth/tokens.js`, `auth/middleware.js`, `thresholds.js`.

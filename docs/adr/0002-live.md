# ADR-0002. Socket.IO через backend

Статус: прийнято; зафіксовано у С9 (24.11.2026).

## Контекст

Історія надходить через REST, поточні вимірювання — з MQTT. Клієнт має використовувати JWT.

## Розглянуті варіанти

1. Socket.IO — сервер перевіряє JWT, керує кімнатами та передає події після запису.
2. Прямий MQTT у браузері — потребує окремої політики доступу брокера; REST polling — зайві запити та залежність затримки від інтервалу.

## Рішення

Socket.IO. Брокер не потрібен браузеру; доступ зосереджено в backend.

## Наслідки

Live залежить від backend; при reconnect React повторно підписується та оновлює кеш.

Підтвердження в коді: `server.js`, `realtime/bridge.js`, `client/src/useDashboard.js`.

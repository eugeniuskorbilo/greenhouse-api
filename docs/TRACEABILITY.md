# Матриця трасованості

Матриця зіставляє всі чотири сценарії ПР1 з фактичним кодом та перевірками. Назви україномовних тестів відновлено за їхнім змістом (у деяких файлах пошкоджено кодування назв). Точні ідентифікатори файлів та HTTP-операції збережено.

| Сценарій ПР1 | Реалізація | Тест / перевірка | Стан |
| --- | --- | --- | --- |
| Перегляд поточних показників | GET `/api/v1/telemetry`, картки React, `telemetry:update` | `api.test.js`: Telemetry, 4 точки [25,35,45,50]; `e2e/dashboard.spec.cjs`: E2E 1, 41% | Реалізовано |
| Налаштування порогу вологості | PUT `/api/v1/devices/{id}/threshold`, редактор агронома | `api.test.js`: Threshold — viewer 403; створення 40, читання 40, оновлення 45 | Реалізовано налаштування, не команда поливу |
| Перегляд історії поливів | Історія телеметрії 1/24 год/7 днів; GET `/api/v1/alerts` | `api.test.js`: фільтри from/to; Alerts — min_value 25, duration_min 2; `logic.test.js`: завершений період | Частково: періоди низької вологості, не журнал фактичних поливів |
| Керування обліковими записами | `seed-users.js` створює демо-користувачів, login/refresh, RBAC | `api.test.js`: Login, JWT 401, Audit viewer 403; немає тесту CRUD користувачів | Частково: RBAC і вхід; CRUD не реалізовано |

Додатково: `api.test.js` Health endpoint: 200 перевіряє SQLite/MQTT; `negative.test.js` відхиляє некоректні MQTT/REST-запити; E2E 2 перевіряє UI-помилку при недоступному REST. ПР1 проєктував автоматичний полив; поточний backend не має API команд або таблиці фактичних поливів. Не підміняти ці сценарії телеметрією під час захисту.
